# 智能药箱 · 大模型联调说明

## 现象

`main.py` 里日志：

```text
[LLM] 网络异常: HTTPConnectionPool(host='127.0.0.1', port=8000): Read timed out
[LLM] 第 1 次调用失败，重试...
```

`config/app.yaml` 当前：

```yaml
llm:
  provider: custom
  base_url: http://127.0.0.1:8000/v1
  model: deepseek-chat
  timeout: 45
```

## 诊断结论（本机）

| 检查 | 结果 |
|------|------|
| TCP 127.0.0.1:8000 | ✅ 通 |
| GET /v1/models | ✅ 200，列出 deepseek-chat / deepseek-reasoner |
| POST /v1/chat/completions | ❌ **卡住 > 60s 超时** |

**不是** 药箱 Python 代码没接上串口/摄像头，而是 **本地大模型代理的「对话」接口卡死**。

`/v1/models` 能回、`/v1/chat/completions` 不回，典型是：

1. 代理进程还活着，但上游（真 DeepSeek / 本地推理）挂了或没网  
2. 代理单线程被上一次请求堵住  
3. 代理在等一个永不结束的上游连接  

## 怎么修

### A. 先重启本地代理（最快）

找到占用 8000 的那个程序（任务管理器 / 你启动代理的终端），**重启它**，再跑：

```powershell
# 自检对话是否恢复（应几秒内返回 JSON）
curl.exe -X POST http://127.0.0.1:8000/v1/chat/completions -H "Content-Type: application/json" -H "Authorization: Bearer sk-deepseek-proxy-2026" -d "{\"model\":\"deepseek-chat\",\"messages\":[{\"role\":\"user\",\"content\":\"说：好的\"}],\"max_tokens\":8}"
```

### B. 代理正常后再开药箱

```powershell
cd "智能药箱系统"
python pc\main.py --port COM3 --mode manual_phone --real-mic --real-llm --real-tts --real-cam --show
```

### C. 临时绕过：换官方 / 其它 API

改 `config/app.yaml` 的 `llm` 段，例如 DeepSeek 官方：

```yaml
llm:
  provider: deepseek
  api_key: sk-你的key
  model: deepseek-chat
  timeout: 45
```

或先关掉真大模型（用本地规则），只测机械臂+相机：

```powershell
# 不加 --real-llm
python pc\main.py --port COM3 --mode manual_phone --real-mic --real-tts --real-cam --show
```

## 注意

- `timeout: 45` 是合理的；再加大只会更久地卡住。  
- 程序会重试 3 次再降级 `unknown`，属于设计内行为。  
- `$READY`/心跳 `$HB` 已通，说明 **STM32/串口正常**，问题在 LLM 代理。
