## 一、结论先说

**发现的 5 项严重问题里有 4 项集中在同一类：PC 端与固件的指令语义不一致。**

这类问题的共同特征是——
**`--mock` 全仿真永远跑通，接上真机立刻失败。**
因为 mock 层完全不校验 ACK/DONE 时序，也完全不区分 MVS/MVC 的真实含义：
`_send_and_wait` 在 `mock=True` 时直接 `return True`，指令发出去就当成功。

所以「mock 53/53 通过 + 端到端 success」**不能证明真机可用**。
这也是本次审查最值得记住的一条。

| 级别 | 数量 | 说明 |
|---|---|---|
| 严重 | 5 | 真机必然失败 / 安全约束失效 |
| 一般 | 4 | 特定条件下失效或误导 |
| 轻微 | 1 | 当前无害，潜在陷阱 |
| 已确认正确 | 8 | 见第四节 |

## 二、严重问题（真机必然失败）

### ★ A1 `$MVS` 语义与固件相反 —— 一设速度就把车停下

| 端 | 指令 | 实际行为 |
|---|---|---|
| 固件 `main.c::HandleCmd_MVS` | `$MVS` | **`CHASSIS_Stop()` 立即停车** |
| PC `chassis_controller.set_speed()` | 发 `MVS,<pct>` | 期望"设速度百分比" |

`HandleCmd_MVS` 的真实实现（固件）：

```c
static void HandleCmd_MVS(const ProtoFrame_t *frame)
{
    (void)frame;
    CHASSIS_Stop();          /* ← 实际上是停车！ */
    PROTO_SendAck("MVS");
}
```

**后果**：PC 每调一次 `set_speed()`，底盘就被停一次。任何"先设速度再运动"的流程都会失败。

---

### ★ A2 `$MVC` 语义与固件相反且缺参 —— 急停发不出去

| 端 | 指令 | 实际行为 |
|---|---|---|
| 固件 `HandleCmd_MVC` | `$MVC,pct` | **设速度百分比**，且**必须有参数** |
| PC `stop()` / `estop()` | 发裸 `MVC` | 期望"立即停止" |

固件侧 `MVC` 的第一件事是取参数：

```c
if (PROTO_GetArg(frame->payload, 1u, arg, sizeof(arg)) == 0u)
{
    PROTO_SendErr((uint8_t)PROTO_ERR_UNKNOWN, "ARG");
    return;                    /* ← 取不到参数直接 return，底盘不动 */
}
pct = PROTO_ArgToInt(arg);
PROTO_SendAck("MVC");
CHASSIS_SetSpeedPct((uint8_t)pct);   /* ← 这是在设速度，不是停车 */
```

**后果**（本项目最危险的一条）：
- `stop()` 发裸 `MVC` → 固件回 `$ERR,ARG` 并 return → **底盘不停**
- `estop()` 同样发裸 `MVC` → **规则 5「全局急停优先级最高」实际失效**
- 更糟的是 `ChassisController.estop()` 只发 `$EST`（停舵机）+ 裸 `$MVC`（无效），
  底盘会带着药继续跑

**这条直接推翻了"急停已落地"的结论。**

---

### ★ A3 固件从不发 `$DONE,MV` —— 每次横移都超时

PC 侧 `ChassisController.move()` 用：

```python
return self._send_and_wait(body, "MV", timeout, wait_done=True)
```

`_send_and_wait` 在 `wait_done=True` 时会等 `$DONE,MV`。

但全固件搜索 `SendDone("MV")` **结果为 0**。`HandleCmd_MV` 只发：

```c
PROTO_SendAck("MV");
CHASSIS_Move(y, x, rx, (uint32_t)ms);
PROTO_SendMvState(CHASSIS_GetSpeedPct(), CHASSIS_IsMoving());   /* 只有 MVSTATE */
```

**后果**：真机上每次 `move()` 都会等满 timeout 再 `return False`——
**车其实动了，但 PC 认为失败**。auto 模式会立刻报 `move_failed` 并进 `align_failed`。

超时时间（`ms/1000 + 3`）：

| ms | timeout |
|---|---|
| 0（连续） | 5.0 s |
| 200 | 3.2 s |
| 685 | 3.7 s |
| 30000 | 33.0 s |

即**每一步横移都白等 3~5 秒**。

### ★ B1 层偏移是死代码 —— auto 模式够不到中/上层

`align_chassis()` 里算了层偏移，然后**再也没用过**：

```python
base_layer_off = self.layer_offset_mm.get(1, 0.0)   # 第 265 行：赋值
shift_mm = shift_cols * pitch_x                     # 之后从未使用 base_layer_off
```

全文件搜索 `layer_offset_mm` 只有 4 处：定义 + 赋值 + 放进返回 dict（写死 0.0），
**没有任何一处变成底盘位移**。

**为什么这是致命的**——几何推演：

货架是**竖直对齐**的九宫格，同一列的三层在货架坐标系里 x 相同。
但本臂（平面 3R，无方位自由度）在三层的可用 x **完全不重叠**：

| 层 | 机械臂可用 x | 配置的 x_start |
|---|---|---|
| 下层 | [163.7, 214.7] | 174.2 |
| 中层 | [120.4, 157.4] | 120.4 |
| 上层 | [0.2, 116.7] | 42.1 |

要靠底盘**前后位移**补偿：`x_arm = X_shelf - delta`

```
layer_offset_mm = {1: 0.0,  2: 53.8,  3: 132.1}
                    ↑ 中层要前移 53.8mm，上层要前移 132.1mm
```

而 `align_chassis()` 只发**横向** `move_lateral()`，**从不发前后 `move_forward()`**。
