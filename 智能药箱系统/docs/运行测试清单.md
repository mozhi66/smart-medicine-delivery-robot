# 运行测试清单

> 智能药箱 · 四轮麦轮融合版 —— 从「没硬件」到「全链路」的分层测试
> 原则：**先 Mock 后真机、先单段后全流**，任何一层红灯都不要往上盖楼。

---

## 0. 环境验收（一切的前提）

```bash
python tools/check_env.py            # 全项体检（解释器/依赖/配置/麦克风/摄像头/串口）
python tools/check_env.py --quick    # 只查依赖与配置（最快）
```

- 看到 `[结论] 没有阻塞项` 再继续；
- 有 `[FAIL]` 按提示装包（或跑 `python tools/install_phase1.py`）。

## 1. Phase-1：环境与模型（不碰任何硬件）

```bash
python tools/install_phase1.py            # 装依赖（大块头 torch 可 --no-torch 跳过）
python tools/dl_models.py                 # 下 FunASR 三件套（paraformer/vad/punc）
python tools/patch_jieba.py --test        # 生成药品词库并验证分词
python tools/phase1_smoke.py              # 冒烟：配置→大模型→(麦克风)→(TTS)→知识库
```

验收点：

- `phase1_smoke` 输出 `[结论] Phase-1 冒烟通过`；
- 有 Key 时 `语义映射` 的 `source=llm`，没 Key 时 `source=mock` 且不报错。

## 2. 固件层（Keil + 静态检查，不上板）

```bash
# 1) Keil 打开 0stm/template.uvprojx，Rebuild（app 组已含 chassis/servo/protocol/main）
# 2) 协议一致性交叉检查（固件 ↔ PC，纯静态）
python tools_cross_check.py               # 期望输出：CROSSCHECK: OK
# 3) 模式约束检查
python tools/check_manual_mode.py         # 期望：manual_phone 约束全部通过
# 4) 旧协议名/坏味道审计
python tools/audit_findings.py            # 期望：未发现残留
```

## 3. PC 单元层（Mock，不连串口）

```bash
python -m pytest tests/ -v                 # 或：python tests/test_pipeline.py
python -m pc.comm.chassis_controller       # 底盘控制器自检（mix 逆解断言）
```

验收点：`test_pipeline` 全绿（协议/运动学/知识库/LLM mock/QR/主流程）。

## 4. 单段真机（接硬件，逐段点亮）

| 段 | 命令 | 看什么 |
|---|---|---|
| 串口 | `python tools/check_env.py` | 串口列表出现 CH340（COM3） |
| 舵机 | `python tools/servo_sweep.py --port COM3` | 四舵机扫角顺畅、无堵转异响 |
| 摄像头 | `python tools/camera_preview.py` | 画面流畅、亮度正常（失败见 camera_check） |
| 扫码 | `python tools/scan_labels_check.py` | 9/9 标签可识别，总览图落盘 |
| TTS | `python tools/tts_speaker_test.py` | 三句播报都出声 |
| LLM | `python tools/phase1_smoke.py` | `source=llm`，类别正确 |

## 5. 全流程彩排（不动真机）

```bash
python tools/phase1_smoke.py --skip-mic --skip-tts   # 已知最稳的一段先绿
```

## 6. 真机全流程

```bash
python pc/main.py                      # 语音→大模型→对列→抓取→扫码→播报
python pc/main.py --mock               # 全仿真（无硬件演示/答辩备用）
```

- 急停：喊「急停」或按 `$EST`（停臂）+ `$MS`（停底盘）；
- 退出：按 `ESC`（后台监听线程置退出标志）。

## 7. 回归节奏（改动后必跑）

1. `python tools_cross_check.py` —— 协议改名/动固件后必跑；
2. `python tools/check_manual_mode.py` —— 动状态机后必跑；
3. `python -m pytest tests/ -v` —— 动 PC 模块后必跑；
4. `python tools/audit_findings.py` —— 每周/发版前跑一次。

---

**红灯排查顺序**：先 `check_env.py`（环境）→ 再 `phase1_smoke.py`（分段）→
再 `tools_cross_check.py`（协议）→ 最后才怀疑硬件。
